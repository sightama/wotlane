# Architecture and plan (decided on 2026-10-09; status as of 2026-10-16)

Goal: a **native PC port that is easy to mod** of War of the Monsters (PS2, NTSC-U). This document says what each piece does, what lives in the repo and what is generated locally.
Direction confirmed on 2026-10-16: **port first**; the decomp only advances on the mod surface.

## The layers
1. **Base: the recompiled game.** [PS2Recomp](https://github.com/ran-j/PS2Recomp) translates the whole executable (5,382 functions, 0 decoding failures, VU0 included) into literal C++
   (`ctx->r4 = ADD32(ctx->r4, 0x20)`), one function per MIPS function, on top of an emulated PS2 RAM. It is unreadable but faithful: logic, classes and libs. Nobody needs to read it.
2. **Runtime (fake hardware).** Separate from the recompiled code, it provides what the PS2 had in hardware: GS and VU1 in software, IOP/sound, IPU/movies, controller, disc.
   In the port, the emulated VU1 and GS are turned off (`PS2X_NO_VU1`, `PS2X_NO_GS`) and the drawing is done by the native layer. The emulated VU1 remains useful as a **reference**: the VU1 vs native check
   ([steps/VU1CHECK.md](steps/VU1CHECK.md)) compares, per triangle, what it would send to the GS with what the native layer draws (more than 99% matched in geometry).
3. **Native layer (what we write).** `native/` in this repo: GPU drawing (raylib) from the scene hierarchy read from EE RAM, particles, shadows, fog, menu text,
   sound (`wotm_snd.hpp`), movies (`wotm_fmv.hpp`), keyboard, native VU0 generated from the microcode. The hooks that run inside the runtime live in `native/runtime/`. This is the port work
   ([steps/NATIVE.md](steps/NATIVE.md)).
4. **Readable layer (decomp).** `src/` + `include/`: `matched`/`equivalent` functions in readable C++. **It does not go into the base port.** It serves (a) for modding: take the readable version of the function, change it and
   rebuild it into the ELF; (b) the oracle; (c) structures and formats that the native layer needs (`include/hieri_types.h`, [FORMATS.md](FORMATS.md)).

## What goes in the repo and what is generated
- **In the repo:** the readable decomp, the type headers, `tools/`, the native layer (`native/`, including `native/runtime/`), the documentation.
- **Never in the repo (rule 1 of [CLAUDE.md](CLAUDE.md)):** the executable, the ISO, the assembly, **the C++ generated by PS2Recomp** (it is game code) and the native VU0 `.inc` (translation of the microcode). Each person generates them from their own ISO.
- **Layout:** PS2Recomp is a **submodule** (`third_party/PS2Recomp`, branch `wotm` of the fork `yanm1103/PS2Recomp`, with the `sqrt` fix). Clone with `git clone --recurse-submodules`.
  The generated code goes into `recomp/` (in `.gitignore`): `recomp/retail/` (retail ELF) and `recomp/nm/` (ELF with the equivalents, guinea-pig runtime). The runtime reads that folder with `-DPS2X_GENERATED_DIR=<repo>/recomp/retail`.
  The fork's CMake receives `-DWOTM_NATIVE_DIR=<repo>/native` and compiles `native/runtime/`; the patch `tools/runtime_patch/wotm-runtime.patch` holds only the seams (CMake, `main.cpp`, taps on VIF1/VU1/memory, scheduler, pad).
- **Runtime build:** `build_runtime.bat` at the root (without LTCG; [steps/RUNTIME.md](steps/RUNTIME.md)). *Still manual:* generating `recomp/` (analyzer + `ps2_recomp` over the ELF). *Missing:* a single script that does this from the ISO.
- The recompiler needs the `SQRT.S`/`RSQRT.S` fix (PR https://github.com/ran-j/PS2Recomp/pull/277); without it, 108 + 76 game functions compute wrong results.

## Copyright and license
- The C++ that PS2Recomp generates is a **mechanical translation of the game's code**, and therefore a protected derivative work: it cannot be published. That is the reason for the model above (each person generates it from their own ISO).
- The readable decomp (`src/`) also derives from the original code. Decompilation projects usually publish it without assets and this is tolerated in practice, but it is a gray area. This is not legal advice.
- Replacing functions does **not** make what remains of the PS2Recomp output publishable: what has not been rewritten yet is still the translated original code.
- The code **in this repository** is GPL-3.0 ([LICENSE](../../LICENSE)), the same license as PS2Recomp. The license does not cover the game. If the distributed port uses the PS2Recomp runtime, the whole falls under the GPL;
  writing our own platform layer is what would leave the project free to change its license in the future.

## Workflow of a mod
1. Choose the function (for example, an AI or a level rule) and open the readable version (`matched` or `equivalent`).
2. Change the behavior (a mod does **not** byte match, by definition).
3. Generate the translated game with the rewrites in place of the originals: `sh tools/wsl/recomp_nm.sh` (WSL: `build_nm.sh nmall` + PS2Recomp → `recomp/nm/`), then
   `build_runtime.bat nm` (Windows: `build_dev_nm`, the "guinea-pig" runtime, same hooks) and `run_live.bat -Build build_dev_nm` to play.
4. Check that **only** what was meant to change changed: `tools\lote.ps1 -Build build_dev_nm` with the same batch (same `-Seed`) as the normal runtime and compare the `resumo.csv` (summary) files;
   for an isolated function, `tools/recomp_oracle` compares the original version with the new one. Equivalents that do not link in the full ELF are listed in `config/nm_all_exclude.txt`.
   **Status:** the chain exists, but the guinea pig still breaks in the fight ([steps/NATIVE.md](steps/NATIVE.md), "Runtime cobaia" (guinea-pig runtime)); it is on hold until the port has HUD and widescreen.

## Pitfalls already paid for
- `sqrtf` in NM C++ comes out with `sqrt.s` in the wrong form: use `eeSqrtf` (`include/vecmath.h`).
- raylib's `TakeScreenshot` comes out empty if the draw batch is not flushed first (`rlDrawRenderBatchActive`).
- The emulated VU1 is too slow to draw with (the fight dropped to ~15 vsync/s) and, without the VU1, the game needs someone to zero `objsInPacket`/`objsInAlphaPacket`; that is why we cut at the scene hierarchy and keep the VU1 only as the reference for the check.
- `pktAddVu1ObjAsm`, `hierTraverseAsm` and `hierCsUpdateAsm` are handwritten assembly with their own convention: do not decompile, replace.
- A host hook without `hostLeaf` freezes the logic when the time slice ends inside it ([NATIVE.md](steps/NATIVE.md), "hooks de host" (host hooks)).
