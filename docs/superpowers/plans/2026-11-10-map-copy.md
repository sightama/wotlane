# Map Creator PR 2 (copy pieces) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A saved map can copy any copyable building, prop or level pickup of its stage (`{"copy": "0x..", "at": [...], "turn": d}`)
and add power-up places (`{"addpowerup": i, ...}`); each copy is a real piece (solid, destructible on its own, its own effects and
rooftop drops), built in guest RAM at `dbInitDb` entry, offline and online.

**Architecture:** The pure part grows in `native/wotm_stagemap.{hpp,cpp}` (strict-float TU): a copy edit kind, the copy-set
rule (per-instance nodes and their in-piece ancestors are copied, geometry is shared), refusal rules and caps, and a copy step in
`apply()` that builds each copy in the reserve (now 4 MB at `0x3BFF000`) from a snapshot of the disc image, rewrites its
pointers, sets its transform, copies its action trees (HAT turned, in-piece DOMINO retargeted), builds and links its collision
paths, and hangs it under a reserve GROUP in the world root's (or the pickup root's) last slot. `wotm_stagemap.inc` passes the
limits in, prints the logs, appends power-up places in the `exportPoints` hook and has a test-only break hook.
`tools/stage_map.py` mirrors the rules (`pieces`, `check`, `make --copy` with riders).

**Tech Stack:** C++17 (runtime, native tests; `/fp:precise`), Python 3 (`tools/stage_map.py`, `tools/ngp.py`), PowerShell
checks (`live_checks.ps1`, `net_checks.ps1`).

**Spec:** `docs/superpowers/specs/2026-11-09-map-copy-design.md` (approved by Jake). Step 1: the spec
`2026-11-09-map-creator-design.md` (read "PR 1 checks" 1a-1j) and the plan `2026-11-09-map-creator-load.md`.

## Decisions made while planning

The controller checks these against the spec before Task 2. "Spec correction" marks where the code says something else than the
spec (evidence given).

1. **Snapshot = disc state.** `apply()` copies the image bytes (`imageSize`) into a buffer at entry when the map has copies,
   before any step 1 write. Copies read their source nodes, action trees and collision paths from that snapshot (a `Mem` over the
   buffer at `kBase`) and are written after the step 1 edits. So a copy of a moved, turned or removed source copies its disc
   state (spec "Saved map"). The world root's last slot is read from the live image (it may hold a step 1 ROTATE).
2. **Copy path = `[header root, wrapper, mapped tail]`** (departs from the spec's "same length, same ancestor GROUPs"). The tail
   is the source path from the piece root down, with copied nodes replaced. The ancestors between the root and the piece (a
   `SWITCH`, `LOD`, `CONTROL`, flagged `GROUP`) do not apply to the copy's drawing (it hangs under the wrapper), so they must not
   apply to its collision either: `hdTraversePath` stops on a `SWITCH` whose active child is not the next path node
   (`src/common/hdTraverse.cpp:164-167`), which would make a copy on 3-MILE (263 pieces under a SWITCH) solid only while the
   original's switch is on. The wrapper copies the root's GROUP flags, so the flags test is the same. Task 1 (2c) counts stock
   paths with a nonzero id1 (other than the world root's 1) or id2 between the root and a piece root, for the record.
3. **Wrappers.** World pieces: GROUP `G` in the world root's (id1 1) last child slot, `G = {old last child, copy1..N}`. Level
   pickups: a GROUP in the last slot of the header root at the top of the source pickup's first-parent chain. Checked on CENTRAL,
   METRO, VEGAS, ISLAND, 3-MILE (scratch script, 2026-11-10): every world root and pickup root is a GROUP with flags 0x3 (world)
   and the pickup roots have one child (CENTRAL 0x600 -> 0x5d0850 -> pickups; METRO 0x2e0 -> 0xc6d380; VEGAS 0x4e0; ISLAND
   0x690; 3-MILE 0x7f00), so the pickup wrapper wraps that child. A wrapper is allocated once per apply, sized for every copy
   edit that would hang under it, and linked into the root's slot by the first copy that applies (part of that copy's writes).
   Its head word is the root's opcode and `isRelocated` bits with both ids 0 (an id1 of 1 would call `viewSetWorldEpNode` on it,
   `src/game/db.cpp:185`); `ctx` (+4) and flags (+0xA) are the root's; its sphere centre is the root's and its radius covers
   its children. The root's own sphere is widened as in step 1 (centre kept). Task 1 (2a) checks all 19 stages.
4. **Per-instance nodes** (copied): `INTERACTIVE_STATE` 39, `DESTRUCTIBLE` 31, `SWITCH` 6, `PARTICLE_EMITTER` 22, `SCRIPT_ACTION`
   41, and a level pickup's GROUP (op 1, id1 in 0x12C0..0x13EB); plus every first-parent ancestor of those inside the piece, plus
   the piece root. Node sizes: GROUP `0x20 + 4k` (u16 +8), TRANSLATE `0x1C + 4k`, ROTATE `0x50 + 4k`, SCALE `0x2C + 4k`, SWITCH
   `0xC + 4k` (u8 +0xB), LOD `0x20 + 16k` (+4), CONTROL `0x20 + 4k` (u8 +0xC), 39 `0x10`, 31 `0xC + 12k` (u16 +0xA), 22 `0xB0`,
   41 `0x60` (`include/hieri_types.h`). Any other kind in the copy set refuses the source (`ACTION_DATA` 23 has a
   variable-length `actionData[]`, `hieri_types.h:639-644`).
5. **Special ids** (refused, spec "Refused sources"). For every node of the source's subtree that `dbsTraverse` hands to
   `dbProcInteractive` (ops 0, 1, 2, 3, 4, 6, 11, 17, 30, 40, 41 with a nonzero id1; `src/common/dbs.cpp:136-360`), refuse an
   id1 below 0x20 (world, sky, font), 0x20..0x400 (monsters), 0xBB8 (pedestrians), 0xFA0..0x11F7 (weapons), 0x11F8..0x12BF
   (effects: HomingBug, OgreMace, SpecFxAnim), 0x13EC..0x144F (power-ups), 0x1B58..0x1C1F (particle textures), 0x1C20..0x2133
   (HUD), 0x2134..0x2327 (scripts), 0x2328..0x3E7F (end points) (`src/game/db.cpp:187-255`). Ops 31 and 39 always go to
   `AddDestruct` whatever their id; for them only the **fixed id1 tables** refuse: SanFran saves 0x275D..0x2762, CANYON2
   pillars 0x2775..0x2777, CAPITOL pillars 0x27AE..0x27B3 (`Destructible.cpp:161-169`) and, added here, the 3-MILE vent and
   stacks 0x2712, 0x2715..0x2718 (`takeHit` drives the level's meltdown script from them, `Destructible.cpp:287-315`). Also added:
   a `PARTICLE_EMITTER` with an id1 in 0x1D4C..0x1D6B (`hierRegisterLocator` keeps one fx per id in `FxToKill[32]`,
   `src/common/hier.cpp:1190-1199`: a copy would take the original's slot).
6. **Animated and scripted sources** (refused): `ANIM_XFORM` 17, `CHAR_INSTANCE` 25, `SKEL_BONE` 35 or `ANIM_SCALE` 38 in the
   subtree; a `CHAR_INSTANCE` or `ANIM_XFORM` on the source's first-parent chain (VEGAS has 4 and 3-MILE 2 world pieces under a
   CHAR_INSTANCE: under the wrapper their objects would lose the character context, `dbs.cpp:147-150`); an `ACT_ANIM` (2) in the
   action trees of its destructibles (spec) and, added, `ACT_CINEMA` 9, `ACT_PLAYERPOS` 11, `ACT_RUNSCRIPT` 12,
   `ACT_AINAVIGATION` 13, `ACT_GENERICEVENT` 14 (a copy would replay the stage's script events,
   `src/game/ActionDispatch.cpp:540-620`).
7. **Caps.** Interactives estimate = 1 (slot 0) + 8 (monster slots) + the `INTERACTIVE_STATE` nodes and the level-pickup and
   HomingBug (0x11F8, 0x1203) nodes reachable from the header roots of the image after the step 1 edits (`parents()`; NULL ends a
   branch) + each applied copy's `INTERACTIVE_STATE` and pickup nodes; a copy that takes it past 1000 is refused. Destructibles
   estimate = `DESTRUCTIBLE` nodes + dispatched non-39 nodes with an id1 in 0x1450..0x1B57 (`db.cpp:228-229`); cap 1400.
   Pickups also take `MemoryStack::global` (`alloc16`, no bounds check, `include/memory_stack.h:58-63`, pool 0x80000 at
   0x800E90): the runtime reads `hi1 - low` of `MemoryStack::global` (0x54D950) at `dbInitDb` entry and passes
   `room - kGlobalKeep`; every stock pickup and every pickup copy counts `kPickupBytes = 0x500` (largest pickup 0x4C0 + its
   0xC list node, both 16-aligned) against it. `kGlobalKeep` (other allocations after `dbInitDb` entry, plus 64 KB) is
   measured in Task 14; it starts at 0x40000. Unit tests run with no pickup limit unless a test sets one.
8. **Action trees.** Per copy, a private copy of every `ACT_GROUP` (`0xC + 4 * count`) and `ACT_TRANSFORM` (0x50) on the way
   from a state's root action to a copied leaf. Leaves copied: `ACT_HATPICKUP` (0x18) only when the copy is turned (offset
   turned by the copy's turn), `ACT_DOMINO` (0x10) when its target (+0xC) is in the copy set (retargeted). A domino whose target is
   outside the source's subtree is kept and logged once per source; one whose target is inside but not copied is kept and logged.
   Other leaves are shared. A memo map per copy handles shared and cyclic trees. (`doGroup` and `DispatchAction` write `delay`
   into hat actions at run time, `ActionDispatch.cpp:270`, `Destructible.cpp:412`: constant values, so sharing them is fine.)
9. **Placement.** A copy goes through the same placement as a move (`planMove`'s boxes and grid-edge clamp), with the source's
   disc place as "old": the copy is clamped inside the grid and logged; `make` mirrors it (`clamp_to_grid()`). A turned TRANSLATE
   source becomes a ROTATE copy; a TRANSLATE with action data (+0xC) is refused when turned (step 1 rule) and `make` errors out.
10. **Grid nodes.** Copies take list nodes from the pool the step 1 removes and moves left, then from the reserve.
11. **Atomic per copy.** All of a copy's reserve allocations and writes (nodes, actions, paths, grid nodes and heads, the wrapper's
    slot and count, spheres) are planned first; a refused copy writes nothing and gives its reserve back. The wrappers are
    reserved up front and keep their space even when every copy under them is refused (review focus 4 still holds: a refused
    copy writes no byte of the image, and nothing links an unused wrapper).
12. **Logs** (built in the .cpp, printed by the .inc, `[stages] <id>: ` prefix):
    - per source, in order of first appearance: `copied 0x2d85a0 x12 (96 KB, 60 grid nodes)` (KB rounded to nearest, bytes taken
      from the reserve by those copies);
    - refusals per (source, reason), first appearance order: `copy 0x18a410 x3 refused: <reason>`;
    - once per source: `copy 0x5c4e10: 2 domino actions point outside it (kept: its copies knock down the original's
      neighbours)`; `copy 0x...: CONTROL|LOD|SWITCH 0x... above it does not hang over its copies`;
    - per clamped copy: `copy 0x2d85a0 (edit 7): kept inside the collision grid's edge, at x y z`;
    - summary, only for a map with copies: `copies: 12 applied, 3 refused; reserve 1234 of 4096 KB; interactives 412 of
      1000, destructibles 330 of 1400, pickup room 300 of 412 KB` (integers, built in the .cpp).
    `applied N edits` keeps counting piece edits only, so the step 1 checks keep matching.
13. **`addpowerup`.** `{"addpowerup": i, "from": [..], "at": [..]}`: appended in the `exportPoints` hook before the step 1
    power-up moves (so `from` is checked against the disc place), in file order; the 64-byte point is copied whole (type +0x2C, arg
    +0x2D, path fields) and its position set to `at`; `numPoints` grows. The same index can be added any number of times, and a map
    can both move (`powerup`) and copy (`addpowerup`) one index. Past 256 points the rest is refused and logged. **Spec
    correction:** the game creates at most 100 power-ups (`PowerUps::CreatePowerUp` returns -1 once `m_count >= 100`,
    `src/game/PowerUps.cpp:243-244`; `m_powerUps[100]`, `include/game/power_ups.h:44`); points past that create nothing (safe).
    The hook notes it: `added N power-ups (M places: the game creates 100 at most)`. A second `exportPoints` in the same load with
    `numPoints` already at the appended total appends nothing (state `g_pupStock`, `g_pupTotal`, reset by `LoadLevelDB`).
14. **JSON.** `Map` gains `copies` (`struct Copy {node, at[3], turn}`) and `addPowerUps` (`PowerUpEdit`). One `edits` list holds all
    four kinds (at most 4096 together); `write()` puts piece edits, then copies, then power-up moves, then power-up additions.
    Keys: `copy`/`at`/`turn` (turn optional), `addpowerup`/`from`/`at`; unknown keys refused. "Digest" in the brief: the
    golden same-bits digest (Task 9); the mod digest already covers `stage.json`'s bytes (`wotm_mods.hpp:120`), nothing to add.
15. **Destroy test hook.** `WOTM_STAGE_BREAK=<seconds>` (test-only, NATIVO.md table): at that game time (g_frame, 60 per second)
    the first applied copy with a destructible goes to its last state through `Destructible::ChangeState(last, false, false)`
    (`ChangeState__12DestructibleibT2`, integer arguments only), called from the slot-0 path of the `Monster::update` hook in
    `wotm_overrides.cpp` (where `vencer` runs). Logs `[stages] break: copy of 0x2d85a0 (interactive 412) to state 3`; 120 frames
    later `[stages] break check: copy state 3, source state 0` (the two `INTERACTIVE_STATE` `whichChild`, read from RAM).
16. **Online.** **Spec correction (scope):** the network's per-frame RAM hash covers only the low 32 MB (`kGuestRam`,
    `native/runtime/wotm_sync.inc:18`), and copies' per-instance nodes live in the reserve above it. `map_copy_online` therefore
    also writes `WOTM_STAGE_DUMP` on both PCs and compares the two image and reserve files byte for byte.
17. **Interactives index order.** **Spec correction:** not every original keeps its stock index. World copies register during the
    world root's traversal, so `INTERACTIVE_STATE`s under header roots after the world root (CENTRAL 0x2510, VEGAS 0x35b0...) and
    all level pickups shift; and pickups register in `LevelPickups::initAfterDbLoad`, which walks `activeList` from its head,
    while `createPickup` pushes each new pickup at the head (`src/game/Pickup.cpp:1176-1186`, `:1203-1211`): pickup copies,
    created last, take the first pickup ids. Deterministic on every PC and nothing keys on stock indices (SanFran saves store the
    id at registration), so harmless; the spec's Known limits get a line.
18. **Demo map** is generated by a committed script, `tools/map_demo.ps1 -Out <stages folder>` (no map folder committed under
    `mods/`: it would show in everyone's stage select). A screenshot goes to `docs/screenshots/<date>/`.
19. **Python mirrors the copy rules and estimates.** `pieces` prints a copy column (`copy 9120 B i1 d1 p0` or `no copy
    (<reason>)`); the disc-backed native test reads that file and compares every piece's verdict, bytes and counts.
